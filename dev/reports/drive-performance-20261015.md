# 運転体験の処理軽量化

比較元: `566a590c55f42f2870265d07ddee67312eb0f06c`。

## 変更

- 走行中だけアニメーションループを継続。開始待ち・一時停止・結果・ホーム・非表示時は停止し、サイズや表示設定の変更時だけ1回描画する。
- 通常描画は最大60fps、既存の軽量モードは最大30fps。物理計算は引き続き全経過時間を消費し、当たり判定用の細かいステップも維持する。
- HUDは100ms間隔で確認し、変わった値だけDOMへ書く。音声パラメータは50ms間隔。発生済みイベントの毎フレーム再検索を廃止。
- Canvasの大きさをキャッシュし、ResizeObserver・画面復帰・表示切替・リサイズ時に更新する。
- 街・駐車車両・建物など、動かない3Dオブジェクトの行列を固定。全シーンの強制再計算を重複実行しない。自転車の関節検索結果も再利用する。
- 3Dのコース生成を必要時まで遅らせ、ホームの3枚のプレビューを空き時間に1枚ずつ生成。コース選択時はプレビュー生成を中断する。
- デザイン、モデル、物理エンジン、採点、保存形式、キャラクター画像は維持。

## 再現可能な比較

`node test-drive-performance.mjs` は120Hzを模擬したDOMテスト。描画自体はスタブなので、数値は処理の呼び出し・書き換え回数であり、実機のFPS・消費電力・総処理時間ではない。

| 10秒の走行 | 修正前 | 修正後 |
| --- | ---: | ---: |
| 描画呼び出し | 1,200 | 600 |
| HUD等のDOM変更 | 8,042 | 118 |
| 音声パラメータ更新 | 1,200 | 200 |

開始待ち・一時停止では、落ち着いた状態の2秒間に発生する描画が240回から0回へ減少。軽量モードは2秒で60回描画する。

`node test-drive-renderer.mjs` は実際の3Dモデル・アニメーションを使い、GPUだけスタブにした検証。120回の描画で行う行列の組み立て回数:

| コース | 修正前 | 修正後 | 削減 |
| --- | ---: | ---: | ---: |
| 駐車車両の陰 | 51,360 | 10,800 | 79.0% |
| 横断歩道の歩行者 | 51,840 | 10,800 | 79.2% |
| 見通しの悪い交差点 | 169,320 | 120,840 | 28.6% |
| 連続ドライブ | 265,320 | 135,960 | 48.8% |

## 検証

- 上記2つの性能回帰テスト、および既存の運転UIテスト。
- 模擬120Hz・軽量30fps・低速15Hzで、物理の経過時間が維持されることを確認。
- 30/60/120Hzでブレーキ停止距離が一致（3.2680277778m）。
- 一時停止、再開、設定ダイアログ、画面復帰、停止中のリサイズ、WebGLエラー時の2D切替、結果画面での描画停止を確認。
- サイズ計測が定常描画120回で1回となること、縦横切替とプレビュー後のサイズ復元を確認。
- 比較元と修正後の4コースを各31時点で比較し、全187/189/242/375ノードの表示状態・メッシュ頂点数・ワールド行列が一致（行列許容誤差1e-9）。実際の画面のピクセル比較ではない。

ブラウザ描画とiPhone実機でのFPS・発熱は未測定。性能改善率を端末全体の速度向上率として解釈しない。
