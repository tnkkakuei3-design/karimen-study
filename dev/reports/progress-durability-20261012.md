# 更新時の学習記録保護

## 対象

同じURL・同じ端末・同じブラウザでの更新時に、成績、回答履歴、復習予定、模試の途中回答・順番・現在位置・残り時間を手動操作なしで引き継ぐ。

## 実装

- 既存保存キーを維持。起動時の復旧が終わるまでアプリを起動しない。
- localStorageの保存に加え、検査値付きの控えをlocalStorageとIndexedDBに自動保存。現在・直前・更新前の記録を保護する。
- 通常保存が容量不足の場合はIndexedDBを利用する。未完了・失敗は通知し、一時的な失敗は10秒ごとに再試行する。
- 破損や保存キー消失から自動復旧。破損した原本も保持する。
- 未対応の新しい形式や復旧不能なデータを、空の記録で上書きしない。
- 新旧の画面・複数タブが記録を巻き戻さないよう検査する。代替保存ではIndexedDBのトランザクションで保存時の版を比較する。
- 途中記録に問題の識別情報を付け、教材の版番号が変わっても問題文・正答・図の識別子が同じなら再開する。
- 設定画面の主案内を「自動保存」に変更。従来のJSON操作は予備の機能として残す。

## 検証

- `test-storage.mjs`：更新前からある記録の自動引き継ぎ、破損復旧、localStorageの控え全消失からのIndexedDB復旧、検査値不一致の拒否、新形式保護、容量不足、両方の保存先の失敗と再試行、初期化の復活防止、起動中・操作中・容量不足時の複数タブ競合を確認。
- `test-progress.mjs`：既存の成績・復習・未回答除外・タイマーに加え、問題が同じ内容版の移行、破損・新形式の上書き防止を確認。
- `test-ui.mjs`：500問・130問の図、模試・学習・復習、タイマー停止、フォーカス復帰時の操作を確認。
- `test-home-install.mjs`：ホーム画面案内とアイコン等の既存機能を確認。
- `npm run build`：公開用ファイルに起動・復旧処理を含める。

容量不足が解消した直後にも、古いタブからの書き込みが新しいIndexedDB記録を上書きしないことを追加検証。競合時は新しい記録を正本として保護し、競合した入力も別の記録として保管する。

IndexedDBはfake-indexeddb、画面操作はJSDOMで検証する。iPhone実機による検証は未実施。

## 残る条件

端末内の全サイトデータ削除・端末紛失にも対応するクラウド同期は未実装。Cloudflare側の新しい実URLも未提供のため、旧URLから新URLへの自動移行は未接続。旧サイトを削除せず、新URL確定後に対象オリジンを限定した自動移行を実装・検証する。任意の移行先や第三者ドメインへ記録を送ることはしない。

ブラウザ内の保存領域はオリジン単位で、同じ端末でも新しいホスト名から旧ホスト名の保存を直接読めない。永続保存の承認・削除方針はブラウザが決定する。
