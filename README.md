# 仮免学科ドリル

教習問題1〜10の各50問、合計500問を、模試・学習・復習で使う静的Webアプリです。
公開先: https://tnkkakuei3-design.github.io/karimen-study/

## 使い方

- **模試**: 第1〜10回から選択。各回の50問を開始するたびにランダムな順番で出題・30分。途中再開では同じ順番を保ちます。45点以上でアプリ内の合格、48点以上で目標達成、50点で満点の花丸。解説は採点後に表示します。
- **学習**: 同じ500問を分野別に原則10問ずつ学習。1問ごとに解説を表示します。図解ノート47テーマもここから開けます。
- **復習**: 実際の誤答・自信なしを共通IDで集約。未回答は正答率や復習予定に加算しません。初回の誤答・自信なしはすぐ復習でき、復習後は30分あけて自信のある正解を2回重ねると卒業します。復習の間違い・自信なしは回数をリセットして30分後に再挑戦。復習開始ごとに順番を変え、途中再開では維持します。待機中の問題は復習を開始できません。全問の先取り練習と回答直後の確認練習は廃止しました。
- 各回の詳細から、制限時間のない「解説付き50問練習」も教材の順番で始められます。模試と別の成績として保持します。

公式試験問題の再現や合格を保証するものではありません。28問は出典付きの代替問題、9問は補足です。各回の開始前と該当設問で表示します。補足も各回の50問に含めます。

## 構成

ビルド不要。ルートを静的配信します。npm依存は検証専用で、利用者の端末では不要です。

- `questions.js`: 有効500問、保管408問、各回の順序・内容版、追加図の対応表
- `learning-content.js`: 既存47テーマのノート・図解・参照資料
- `model.js`: 保存、旧記録の移行、採点、復習スケジュール
- `visuals.js`: 既存の確認済み設問図・画像出典・花丸・ノート見本
- `app.js`, `index.html`, `styles.css`: 3タブ、問題、結果、ノート、設定の画面
- `image-*.png` と `data/assets/`: 既存図と追加99画像（104設問で使用）

## Cloudflare Pagesへの移行

GitHubの同じリポジトリを連携し、次の設定で公開します。

| 項目 | 値 |
| --- | --- |
| 本番ブランチ | `main` |
| フレームワーク | なし |
| ビルドコマンド | `npm run build` |
| 出力ディレクトリ | `dist` |
| ルートディレクトリ | リポジトリのルート（空欄） |
| 環境変数 | `SKIP_DEPENDENCY_INSTALL=true` |

Node.jsは`.node-version`の24.15.0を使用します。ビルドは依存なしで内容・画像を検証した後、実行ファイルと画像を`dist/`にまとめます。テスト・作業報告・検証用画面は公開物に含めません。アイコンを含む内部参照は相対URLなので、GitHub PagesのサブディレクトリとCloudflare Pagesのルートの両方で動きます。

同じURL・同じ端末・同じブラウザでのサイト更新は自動引き継ぎです。回答・成績・復習予定・模試の残り時間のために、手動で書き出し・読み込みを行う必要はありません。

Cloudflareへの移転でホスト名が変わる場合、ブラウザの保存領域も変わります。新URLが確定してから、旧URLを経由する自動移行を接続・検証してください。現時点では移転先の実URLが未確定で、自動移行はまだ有効ではありません。ユーザーによるJSONの受け渡しを移転の必須手順にはしません。ホーム画面への追加とQRコードは新URLで作り直します。

新URLの公開・引き継ぎ確認までは旧サイトを残します。公開先の切り替えはCloudflare側の成功を確認してから記録してください。

## 問題と内容版

有効IDは301〜800。1回50問を維持し、類似する設問を回をまたいで削除しません。3〜10の旧 `set14〜21` は新しい回番号ではありません。`WORKSHEETS.orderedIds` と `worksheet` を正とします。

新規出題は `Q` の500問のみ。`ARCHIVED_Q` の408問は過去の記録表示用です。ノートからの練習も有効500問に限定します。

`isReplacement`, `replacementSource`, `sourceRef`, `isSupplemental` を保持してください。設問画像は `ADDED_ART` と既存 `IMGQ` / `VISUALS` から表示し、解説用の図や参考問題リンクは解答後に表示します。

本文・正答・図の意味を変えるときは、その回の `contentVersion` と共通の `CONTENT_VERSION` を更新します。現在の内容版は引継ぎ時の本文・正答・説明・図ID・代替/補足フラグ・追加画像ハッシュに基づきます。既存画像や共通図の意味を変更する場合も内容版の更新が必要です。IDの変更や再利用は禁止です。

## 学習記録

新しい保存先は `karimen-study-v4`。旧 `karimen-study-v2` と `karimen-drill-miss` は削除・上書きしません。v4がないときだけ旧記録を移行します。旧記録との継続同期はしません。

- 有効500問の回答・誤答・復習予定は引き継ぎます。
- 旧50問練習の得点と花丸は `guidedResults` に保持します。30分模試の `mockResults` とは混算しません。
- 除外408問、旧判定A〜C、旧ランダム模試、対象外の途中セッション、未知IDは `legacyArchive` に保管します。設定から閲覧・書き出しできます。
- 当時の得点 `scoreSnapshot` は現在の正答で再計算しません。前回差は同じ回・内容版・採点方式だけを比較します。
- 最高点は直近10回から落ちても保持します。同点は「更新」と表示しません。
- 同じ試行は `attemptId` で重複保存を防ぎます。
- 手動の途中終了は履歴に残し、回答した問題だけで正答率を表示します。50問の合否・最高点・前回比較には含めません。未回答は結果画面で別に確認・学習できます。
- `statsPolicy: 1` では未回答を学習統計に加算しません。以前のv4記録は保存済みの回答履歴に基づき一度だけ補正し、補正前の集計を保管します。実際の回答の時系列を復元できない旧記録では、既存の復習予定を保守的に保持します。
- 模試の出題順は新規開始時だけFisher–Yatesで並べ替え、`session.ids` と回答・フラグを同じ位置で保存します。再読込み・再開・インポートでは再抽選しません。各回50問の所属を順序に依存せず検証し、従来の順番で保存した途中記録も継続できます。結果画面には出題順と元の回・問題番号を併記します。
- 模試は問題画面が前面にある間だけ制限時間が進みます。別アプリ・別タブへの切替、フォーカス喪失、画面を離れる操作、「中断」で残り時間を保存して停止します。画面復帰時に自動再開し、中断・リロード・読み込み後は「続きへ」で再開します。表示中も5秒ごとに残り時間を保存します。旧版の固定終了時刻しかない途中記録は、移行時点で残っている時間を引き継ぎます。時間切れは50問で一度だけ採点しますが、未回答は学習の正答率や復習予定に加算しません。
- 保存失敗は画面に表示します。壊れたJSONは保管し、保管できない場合は元データへの上書きを止めます。
- 書き出しには途中の回答と以前の記録も含みます。読込み前の現記録も保管します。
- 別タブの更新を受けたタブは操作を止め、再読み込みを案内します。

### 更新時の記録保護

- 保存キー `karimen-study-v4` はリリース番号・教材の版・公開先のパス変更で変えません。保存形式を更新するときは旧形式からの移行を追加し、このキーを削除して初期化しないでください。
- `startup.js` が `progress-storage.js` の復旧確認を終えてから `app.js` を読み込みます。起動順を戻すと、復旧前の空の記録がバックアップを上書きする危険があります。
- 通常の保存と別に、検査値付きの直近の控えをlocalStorageとIndexedDBへ自動保存します。IndexedDBには更新前の記録も保持します。壊れた保存からは正常な控えを自動的に復元します。
- localStorageの容量不足時はIndexedDBに保存し、書き込み完了・失敗を画面へ反映します。一時的な失敗は10秒ごとに再試行します。どちらにも保存できない場合、成功とは表示しません。
- 別タブの上書きを検出し、IndexedDBへの代替保存でもトランザクション内で競合を確認します。新しい保存形式や復旧できない破損データは空の記録で置き換えず保護します。
- 途中の問題には問題文・正答の識別情報を保存します。教材の版が変わっても同じ内容なら、その問題順・回答・位置から再開できます。実際に内容が変わった途中記録は以前の記録として保管します。
- ブラウザに永続保存を要求しますが、許可はブラウザが決定します。端末全体のデータ消去、別ブラウザ・端末、別オリジンへの自動同期を保証するサーバー保存は未実装です。
- 保存の検証は `node test-storage.mjs`。通常の `npm test` にも含まれます。

## 地域のお店・食券ガイド

模試ホームの「教習の合間に、まちのごはん」から開けます。直接リンクは `#town`、店舗詳細は `#town/kirakira` の形式です。既存の青・白・紺を保ち、食券表示に緑を使っています。

- 提供された案内表から所在地確認済みの14件を掲載。店名・メニュー検索、種類別表示、端末内のお気に入り、店舗詳細、電話、Googleマップの徒歩経路を用意しました。
- 営業時間は案内表の記載です。リアルタイムの営業中表示、星評価、徒歩分数、食券の対象価格は推測していません。施設では飲食店が食券対象であることを明記しています。
- 14件の店舗・施設はGoogleの埋め込み応答の店舗名・住所と照合し、アプリ内地図を設定済みです。「365」は店名・電話番号で所在地を特定できず、掲載から除外しています。市の中心点や別店舗のピンで代用しません。地図応答と店舗切替は確認済みですが、スマホ実機の描画は未確認です。調査記録は `dev/reports/town-maps-20261012.json` を参照してください。
- お気に入りは独立した `karimen-town-bookmarks-v1` へ保存します。学習記録・途中回答・採点・教材データは変更しません。問題に回答中はお店画面を開きません。

### 実店舗の写真

2026年10月12日の写真対応で、15件すべてに静的JPEGを配置しました。Google APIの設定は不要です。「いとま〜る」は実施設の写真2枚（2022年3月撮影）、その他14件は商用再利用可能な料理素材を「料理イメージ」と明示して使います。14件の実店舗・実メニュー写真を取得できたという意味ではありません。実店舗の写真は引き続きGoogleマップや公式Instagramへのリンクでも確認できます。

画像12枚の作者・元ページ・ライセンス・検査値・店舗との対応は [写真の出典一覧](assets/town/SOURCES.json) に記録しています。公開されているJPEGをそのまま同梱し、画面では表示枠に合わせてトリミングします。撮影者と出典・ライセンスへのリンクは写真に併記し、小さなホームの写真では「写真の出典」を開くと確認できます。

`town-config.js` の店舗ごとの写真を、次の方法で実店舗写真へ差し替えられます。

1. 店舗提供または利用許諾を確認した写真を `assets/town/` へ置き、`photos` にURL・代替テキスト・提供者名・許諾記録を登録し、`selection` の該当店に設定する。料理イメージではない写真は `kind: 'venue'` を使う。
2. Maps JavaScript API / Places API (New) を有効にした課金設定済みプロジェクトのブラウザ用キーと、各店を電話・所在地で照合したPlace IDを設定する。必要に応じてMaps Embed APIも有効にする。キーは公開サイトのHTTPSリファラーと使用APIで制限し、割り当て上限を設定する。その店舗の静的写真の選択を空にするとGoogle連携に切り替わる。

静的写真は同じ公開サイトから遅延読込みします。任意のGoogle連携を設定した場合も、写真は表示される位置に来たときだけ取得します。Googleの写真にはGoogle Maps表記・撮影者の氏名とリンク・写真の提供元リンクを表示し、画像やPhoto URIをlocalStorage・IndexedDBに保存しません。取得失敗時はGoogleマップへのリンクを使えます。Places利用料金や利用条件は設定時に[Googleの公式資料](https://developers.google.com/maps/documentation/places/web-service/usage-and-billing)を確認してください。

`node test-town.mjs` は検索・日本語入力・お気に入りの再読込みと失敗・地図の代替リンク・直リンク・学習記録保護・写真プロバイダーの遅延読込みと出典表示を確認します。今回追加したガイドのブラウザ描画・スマートフォン実機・実際のPlaces API応答は未検証です。上記の既存画面の表示確認には、この追加画面を含みません。
